# 知微应用商店 · Zhiwei Store

一个应用商店，聚合官方商店、第三方商店与开源平台的下载源。搜索一次，看全部来源与全部版本。

## 它解决什么

安卓应用散落在各处：官方商店有国内版，第三方站有历史版本，开源项目只在 GitHub Releases 发 APK。这个商店把它们的**下载源**汇聚到一处，按包名合并同一条目，再让你挑来源与版本。

## 已接入的源（8 个）

| 源 | 类型 | 说明 |
| --- | --- | --- |
| F-Droid | 开源仓库 | 索引落本地 SQLite，可离线搜索；清华 / 中科大 / 北外 / 阿里云镜像自动测速 |
| IzzyOnDroid | 开源仓库 | F-Droid 兼容仓库，收录大量 GitHub 上架应用（独立索引库） |
| GitHub Releases | 开源平台 | 直接解析 release 里的 APK 资产，识别 arm64 / armv7 / x86，官方直连 + ghfast.top 加速双线路 |
| Aptoide | 第三方聚合 | 一次拿到 Aptoide 生态多家店铺版本，结果带「店铺」标签 |
| APKPure | 第三方 | 收录 Google Play 应用及历史版本 |
| APKCombo | 第三方 | 提供多架构 APK 与历史版本 |
| 酷安 | 第三方社区 | 需在设置里填 Access Token，未填时自动跳过并提示 |
| 应用宝（腾讯） | 官方商店 | 国内直连，搜索走页面同源接口 |

新版开关在「我的 → 应用源」里，可单独启停并一键检测可用性。

## 构建与发布

**不在本地打包。** 正式包由 GitHub Actions 构建：

- 推送到 `main`：构建 debug + release，产物上传为 workflow artifact
- 打 tag（`v1.0.0` 这样）：额外自动创建 GitHub Release，正文取 `.github/RELEASE_NOTES.md`
- 本机只跑 Kotlin 编译做验证

发布签名固定，避免覆盖安装时报签名冲突：仓库内 `keystore/zhiwei-release.jks`（PKCS12，别名 `zhiwei`），由 `tools/make_keystore.py` 生成。CI 也可改用 Secrets 注入：`SIGN_KEYSTORE_BASE64`、`SIGN_STORE_PASSWORD`、`SIGN_KEY_ALIAS`、`SIGN_KEY_PASSWORD`。

## 代码结构

```
app/src/main/java/com/zhiwei/store/
  core/     Http、JSON 工具、流式 JSON 读取器（解析 18MB 索引不 OOM）、格式化
  model/    AppItem / AppDetail / DownloadOption / MergedApp / DownloadTask
  data/     StorePrefs（偏好）、StoreRepository（并发聚合 + 跨源合并 + 健康检查）
  source/   StoreSource 接口 + 8 个源实现 + SourceRegistry
  source/fdroid/  F-Droid 索引解析与 SQLite 落地
  download/ 下载器、通知、APK 安装
  ui/       主题、通用组件、首页 / 搜索 / 详情 / 下载 / 我的
```

新增一个源 = 实现 `StoreSource`（id / name / kind / note / homepage / search / detail / healthCheck）+ 在 `SourceRegistry` 注册一行，UI 与聚合搜索自动生效。

## 技术约束

- 不引入 OkHttp / Coil / DataStore，全部用 `HttpURLConnection` + 自研图标缓存 + SharedPreferences，控制体积
- F-Droid 索引 18MB，用自研 token 级流式解析器（`JsonStreamReader`），写库采用「新表灌数据 → 原子改名」策略，解析失败保留旧数据
- minSdk 24 / targetSdk 35 / Java 17 / AGP 9.0.0 / Kotlin 2.3.10

# Zhiwei Store

One app store that aggregates download sources from official stores, third-party stores and open-source platforms. Search once, see every source and every version.

## Why

Android apps are scattered: official stores ship region builds, third-party sites keep older versions, and open-source projects publish APKs only on GitHub Releases. This store aggregates those **download sources**, merges results by package name, and lets you pick the source and version.

## Sources (8)

| Source | Kind | Notes |
| --- | --- | --- |
| F-Droid | Open source repo | Index stored in local SQLite for offline search; four China mirrors are speed-tested automatically |
| IzzyOnDroid | Open source repo | F-Droid compatible repo, lots of GitHub-published apps (own database) |
| GitHub Releases | Open source platform | Parses APK assets from releases, detects arm64 / armv7 / x86, offers direct plus ghfast.top mirror links |
| Aptoide | Third-party aggregator | Returns versions from many stores inside the Aptoide ecosystem, tagged with store name |
| APKPure | Third-party | Google Play apps plus historical versions |
| APKCombo | Third-party | Multi-arch APKs and older versions |
| Coolapk | Third-party community | Requires an access token; skipped with a hint when unset |
| Tencent MyApp | Official store | Directly reachable in mainland China |

Every source can be toggled and health-checked under "Mine → Sources".

## Build & release

**No local packaging.** Release builds run on GitHub Actions:

- Push to `main`: builds debug + release, uploads artifacts
- Push a tag (`v1.0.0`): also publishes a GitHub Release using `.github/RELEASE_NOTES.md` as the body
- Local machine is only used to type-check Kotlin

Signing is fixed to avoid "package conflicts with an existing package" on upgrade: `keystore/zhiwei-release.jks` (PKCS12, alias `zhiwei`), generated by `tools/make_keystore.py`. CI may override with secrets: `SIGN_KEYSTORE_BASE64`, `SIGN_STORE_PASSWORD`, `SIGN_KEY_ALIAS`, `SIGN_KEY_PASSWORD`.

## Layout

```
app/src/main/java/com/zhiwei/store/
  core/     Http, JSON helpers, streaming JSON reader, formatters
  model/    AppItem / AppDetail / DownloadOption / MergedApp / DownloadTask
  data/     StorePrefs, StoreRepository (concurrent aggregation + merge + health)
  source/   StoreSource interface, 8 implementations, SourceRegistry
  source/fdroid/  F-Droid index parsing and SQLite storage
  download/ downloader, notifications, APK install
  ui/       theme, widgets, home / search / detail / downloads / settings
```

Adding a source = implement `StoreSource` (id / name / kind / note / homepage / search / detail / healthCheck) and register one line in `SourceRegistry`. UI and aggregated search pick it up automatically.

## Constraints

- No OkHttp / Coil / DataStore: `HttpURLConnection`, a hand-rolled icon cache and SharedPreferences keep the APK small
- The 18 MB F-Droid index is parsed by a token-level streaming reader (`JsonStreamReader`); data is written to a new table then atomically renamed, so a failed parse keeps the old data
- minSdk 24 / targetSdk 35 / Java 17 / AGP 9.0.0 / Kotlin 2.3.10
